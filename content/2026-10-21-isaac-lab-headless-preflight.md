# 别先把 GPU 跑满：Isaac Lab 的第一份成果应是环境证据

准备在 Isaac Lab 做强化学习时，很容易从“装好了”直接跳到“开一晚上训练”。但第一份应该保存的成果，不是 loss 曲线，而是一条能回答这些问题的运行记录：哪个 release / 镜像、哪版 Isaac Sim、什么 GPU / driver、日志和 checkpoint 写到了哪里、当前是纯 headless 还是会开相机录视频。

我这次把这一步整理成了 [无界面训练前检查路线](../roadmap/isaac-lab-headless-preflight.md)。它把首次尝试拆成 E0–E5：环境事实、初始化、单步任务、短训练、可视检查、可复跑。每一步只扩大一个变量，也把“训练进程没报错”“出现视频”“策略完成任务”“能迁移到真机”分成不同证据等级。

对资源有限的开发者，这种顺序特别重要：headless 适合远程机器，但不开渲染也不等于策略正确；容器能启动，也不等于 GPU、日志和 checkpoint 目录都可用。先把版本、权限和产物路径固定下来，才值得投入更长训练。

这篇内容只核验了 Isaac Lab 官方文档和仓库；我没有安装 Isaac Lab / Isaac Sim、拉取容器、训练任务或生成 benchmark。因此路线里的命令需要在目标 release 与实际硬件上重新确认，不能当作本仓库的复现结论。

适合谁：准备上手 Isaac Lab、没有本地显示器或要在远程 Linux / 容器运行仿真的开发者。硬件边界：完整 Isaac Sim 工作流通常需要 NVIDIA GPU，并以目标 release 的官方系统要求为准；没有运行记录前，不要承诺 GPU、显存、成本或训练时长。
